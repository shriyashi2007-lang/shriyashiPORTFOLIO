# Implementation decisions

- On 27 October, the user supplied a specific forest-fairy image and asked for the fairy to occupy the whole screen, with flowers falling as she enters and reveals the website. This supersedes the small illustrated/orbiting fairy below. The exact supplied image is preserved unedited in `public/assets/fairy/forest-fairy.png`. The intro is a full-viewport photographic composition with a gentle CSS entrance, softly extended forest background, full-screen petals from the first phase, and a flower-overlay dissolve into the website. It does not claim to be an animated video or separately animated photographic wings. Existing Skip/Escape, focus containment/restoration, scroll lock and reduced-motion bypass remain.

- The user then explicitly requested a lotus-pink fairy opening: circular flight, sparkles and sprinkled flowers before the portfolio appears. Added an original vector fairy, animated wings, two 1.6-second orbits, a 2.2-second flower/lotus reveal and a 650ms fade. This intentionally supersedes the earlier decision to omit an opening scene. It plays on full page loads, with Skip/Escape controls and immediate bypass for reduced motion. The background site is inert and hidden from assistive technology only during the scene; focus and scrolling are restored when it ends. Timers/listeners are cleaned up on unmount. Artwork uses inline SVG and short-lived CSS animations, not video or a network-dependent loader.

- On 26 October, the user requested a new background and palette using a supplied textile-and-lotus reference. This supersedes the earlier midnight theme: burgundy velvet canvas, antique gold framing/buttons, ivory text, rose petals, and muted copper/olive project panels. The supplied image is stored in `public/assets/theme/ornate-reference.png` and used as a decorative outer background. The content panel and lower gradient keep the embedded search overlay out of the design. Grain is an original SVG texture; the user image itself is unedited. Styles are in `src/styles/heritage.css` and the recoloured base theme. Mobile and desktop accessibility/layout checks passed at four widths after this change.

- Built in `portfolio/` because the parent workspace is a separate DevTrack app with existing uncommitted work. Parent application files were left intact. The user later explicitly requested publishing source to `shriyashi2007-lang/shriyashiPORTFOLIO`; a separate clean clone is used so no DevTrack files enter the portfolio repository. Website hosting is a separate step.
- Used the attached implementation prompt as the source for biographical facts. Its referenced resume and video were not actually attached, so neither was independently verified. No resume PDF is manufactured. Education, scholarship and July 2026 simulation details are user-provided facts, not claims independently verified by certificates.
- GitHub username is verified as `shriyashi2007-lang` from all supplied URLs. It is a usable default with an environment override, rather than requiring the user to supply it again.
- Seven unique projects are curated; the repeated resume builder URL is deduplicated. Public repository metadata was captured in `repository-evidence.json` on 25 October 2026. Public GitHub connector was unavailable; metadata and READMEs were retrieved directly over HTTPS.
- Descriptions and technology tags for DevTrack, Resume Builder, Student Scoreboard, AI Productivity Dashboard, Trinethra and Async Weather Tracker are based on their READMEs. Weather Data Visualizer had no available README; its description comes from the supplied brief and its exact repository name/language match. No guessed project-to-repository mapping was used for PaperMind AI, University Dashboard or Campus Energy Use Dashboard.
- Four repository homepage URLs responded HTTP 200. They are the only demo links. Other repo homepages are null. No live screenshot, outcome or metric has been fabricated.
- Consolidated biographical facts and certificate records in `config.ts` so identity facts have one editing location; skills and repository curation have their own data modules. Related presentational primitives and sections share files to avoid redundant tiny modules.
- The user subsequently supplied a Squarespace screenshot and explicitly requested that theme with attractive colours. This supersedes the original light-only palette: charcoal `#171F23`, midnight blue, ivory `#F3F1E9`, seafoam `#AED8C9`, muted text `#B0C0C6`, plus deep plum, sage and bronze project artwork.
- Built an original CSS phone illustration with sculptural teal petals and the S monogram, inspired by the supplied visual composition. It is labelled as original CSS artwork. No Squarespace branding or photography was copied. Missing images use no image element.
- Self-hosted fonts through Fontsource, Latin subset only; fonts use swap. No unnecessary preloads. Tableau uses a Lucide analytics icon because the installed Simple Icons package does not export that brand icon.
- Hero and section headings use regular-weight Playfair Display for the requested editorial look. UI and primary body copy use Inter, with restrained Caveat flourishes and occasional Source Serif 4 prose. Theme overrides live in `src/styles/theme.css`.
- CSS smooth scrolling only; no Lenis or Three.js. Reduced motion disables smooth scrolling and decorative animation. After profiling the final dark theme, removed the full-screen intro wipe, first-screen transform animation and watermark parallax to reduce startup work. Scroll reveals, timeline drawing, counters, role rotation and hover interactions remain. The actual hero serif font is preloaded for faster first paint.
- The first project spans two desktop columns; subsequent cards form a responsive collage. Content has honest placeholders, no skill percentages or unverified GitHub statistics.
- The mobile navigation includes all nine sections, focus containment, Escape dismissal, scroll lock and trigger focus restoration. Desktop shows primary links, with remaining anchors available in the footer.
- Certificates are disabled until both configured and present in the build-time asset inventory. PDFs open externally; an image lightbox is not needed because no image certificates are configured.
- SIH 2026 is neutral pending confirmation, excluded from the hackathon count. No unverified result is shown. Phone and absent social URLs are hidden.
- Formspree is the implemented provider. An absent endpoint renders a direct-email state. Web3Forms and EmailJS are not advertised as functional without adapters.
- Missing resume cannot satisfy the prompt’s “resume returns 200” test honestly. The implemented verification instead checks that missing resume actions are disabled. Add the actual file to enable both preview and download.
- Deployment needs a hosting destination/account configuration and is left documented, not claimed. Open Graph image paths are relative until a real domain is available.
